# FiLM-L 表示隐私审计：训练前约定

日期：2026-10-20。状态：**仅完成协议和烟测；尚未运行正式攻击评价。**

## 1. 研究问题与边界

本轮不把“原始字段不上传”直接等同于隐私保护，而是检验：在冻结的 FiLM-L 中，融合端看到协议消息后，能够在多大程度上恢复各节点的本地输入。

本轮使用的保护目标是模型实际接收的预处理输入 `x1/x2/x3`。它们已经经过训练期截尾、填补、稳健尺度或类别编码；在没有逐字段逆变换核验以前，结果只称“预处理输入的可恢复性”，不称原始 CSMAR 数值被精确恢复。

本轮是表示反演和属性推断实验，不称“破译”，也不构成差分隐私、同态加密或安全多方计算证明。

## 2. 威胁模型

主威胁为**诚实但好奇的融合端**：它按协议执行推理，知道模型结构和冻结参数，并拥有较早年度的一批辅助企业样本，利用这些样本训练攻击器，随后攻击后续年度消息。

当前代码与汇报中的协议边界并不完全相同，正式实验同时保留两种视图，且以汇报所用的部署视图为主：

1. **实现视图**：模型内部已先完成 FiLM 调制，融合模块看到
   `m1=[h1,q1]`、`m2'=[h2',q2]`、`m3=[h3,q3]` 和行业码。
2. **部署视图（主）**：市场、财务、治理和审计逻辑消息分别到达融合端，融合端看到
   `h1,h2,h3,q,industry,c,r`，再计算
   `h2'=h2+r[gamma(c)⊙h2+beta(c)]`。

如果审计与治理同属一个物理机构，第二种视图仍是融合端可见信息的保守上界。正式报告必须同时写明拓扑，不把较弱实现视图冒充真实攻击面。

最终交付预测采用六个随机种子模型集成。因此隐私审计必须区分：

- **单模型视图**：攻击者只看到某一个种子模型的表示；
- **六模型联合视图（部署主口径）**：同一企业为六套本地编码器生成的表示全部到达融合端，攻击者联合使用它们。重复的 `q/r/industry` 在攻击输入中只保留一次，但六套 `h1/h2/h3/c` 全部保留。

若未来改成节点内集成后只上传一个汇总表示，需要单独证明其预测与现行六模型集成的关系；本轮不假设这种尚未实现的协议。

行业码是当前协议声明的公共融合条件；审计控制码 `c` 和匹配位 `r` 在部署视图中有意发送。二者不作为“被意外推断”的隐私成功指标，但需要报告它们在接口中被直接暴露。若后续要求审计类别也保密，必须重新设计协议。

## 3. 冻结对象、年度与攻击切分

- 主模型：`控制消息架构/20261018-v1` 中的 `FiLM-L`。
- 模型种子：42、100、17、223、483、907；模型权重不更新。
- 目标年度：2020、2021、2022。
- 对每个目标年度使用其同一冻结数据包：split 0 训练攻击器，split 1 选择固定候选中的攻击器，split 3 只作最终评价；split 2 不参与攻击器调参。
- 正式评价之前不得读取 split 3 的攻击指标；本目录烟测只访问 2020 年 split 0 的前 384 行。
- 所有尺度、PCA、随机投影和攻击器参数只从 split 0/1 得到。

## 4. 攻击对象

### 4.1 单节点反演

- `h1 -> x1`；
- `h2 -> x2` 与 `h2' -> x2` 分开报告；
- `h3 -> x3_base`，其中 `x3_base` 只含治理/事件的原16维，不把已显式发送的7维审计槽算作“恢复成功”。

### 4.2 融合端全视图反演

- 主部署视图 `[h1,h2,h3,q,industry,c,r] -> xi`；
- 实现视图 `[m1,m2',m3,industry] -> xi` 作为较弱对照；
- 另比较 `h2`、`[h2,c,r]` 和全视图对 `x2` 的恢复，量化审计控制信息是否增加财务恢复能力。
- 上述比较同时报告单模型和六模型联合视图。若联合视图攻击更强，应按最终部署视图判断隐私风险，不能只展示单模型攻击。

### 4.3 属性推断

属性集合在正式评价前从字段字典固定，不能按结果选择。第一轮包括：

- X1 市场类型哑变量和缺失状态；
- X2 各财务字段的缺失状态，以及预先登记的少量二值/分箱敏感属性；
- X3 高管事件状态与缺失状态。

违规标签是模型的预定输出，行业和审计控制是预定共享输入，不将其高可预测性包装为“隐私攻击成功”。成员推断和训练梯度反演留到第二阶段。

## 5. 攻击器与对照

正式第一轮固定以下攻击器，不依据 split 3 加模型：

1. 常数攻击器：连续字段输出攻击训练集均值，二值字段输出训练频率；
2. 多输出 Ridge：`alpha ∈ {0.1,1,10,100}`，仅由 split 1 选择；
3. 两层 MLP：隐藏宽度固定为 `min(256,2×输入维数)`，ReLU、固定种子、split 1 早停；
4. 同消息维数 PCA 重构；
5. 同消息维数高斯随机投影加 Ridge。

白盒优化反演（已知本地编码器并求解 `E_i(xhat)≈h_i`）只作第二阶段强攻击上界，不与第一轮同时调参。

## 6. 指标与统计口径

- 连续字段：逐字段 RMSE、以攻击训练集标准差归一的 NRMSE、R²、Spearman；先逐字段计算，再宏平均，避免X2字段数支配总体结果。
- 二值字段：AUROC、AUPRC、F1和balanced accuracy；恒定字段不计算AUROC并单列支持量。
- 节点级汇总：逐字段宏平均及分位数；不把所有字段扁平后只报一个数字。
- 年度合并：年度等权；区间按企业聚类重抽样，同一企业跨年度共用抽样权重。

若攻击器相对常数对照的误差下降区间不跨0，或预登记敏感属性AUC的95%区间下界高于0.5，则认定在该攻击模型下存在可利用泄漏。该判断是经验攻击证据，不是对所有攻击者的安全定理。

## 7. 后续防护分支的启动条件

只有正式隐私审计发现可利用泄漏后，才训练防护模型。首选候选是攻击者感知表示学习：

`L = L_task - lambda * L_attack`。

普通降维、FP16/INT8量化和高斯噪声作为对照。`lambda`和噪声强度必须在新协议中事先固定候选；效果用“前10%名单、Top2类型提示、攻击成功率、实际字节”四项共同判断。差分隐私需要另行定义企业级邻接、裁剪和组合预算，不在第一轮自动声称。

## 8. 停止与报告纪律

- 第一轮不做梯度反演、同态加密或多方安全协议，避免同时改变威胁模型。
- 不用互信息估计替代攻击实验。
- 不将低维、不可一一映射或单个攻击器失败表述为“不可逆”。
- 不覆盖旧模型、旧预测或通信结果；所有新产物只写本目录。
- 正式攻击运行前，需先由分类闭环冻结效用指标，并由主任务确认本文件中的部署拓扑。

## 9. 正式执行补充冻结（2026-10-20，打开测试折之前）

分类闭环已经冻结，主任务已授权正式攻击。下列实现细节在读取 split 3 攻击结果前固定：

- 年度为 2020、2021、2022；单模型固定 seed 42，联合视图固定六个既有种子 42、100、17、223、483、907。
- split 0 用于攻击器训练，split 1 只用于 Ridge 的 `alpha` 选择、MLP 早停以及 Ridge/MLP 二选一；选择完成后不把 split 1 回填训练。split 2 不加载。split 3 只运行一次正式评价。
- 六模型部署视图去除重复信息后为 802 个攻击特征（另加公开行业码形成 803 列）；当前实现视图为 753 个攻击特征（另加公开行业码形成 754 列）。若物理上逐套上传，前者为 822 floats，后者为 768 floats；去重只减少重复列，不改变攻击者掌握的信息。六模型视图已经超过受保护输入的273维（2020/2021）或280维（2022），属于过完备消息，不能沿用单模型“低维压缩”的隐私解释。
- 实际攻击任务为：`h1→x1`、`h2→x2`、`h2'→x2`、`h3→x3_base`，以及部署/实现全视图分别恢复 `x1+x2+x3_base`。全视图结果同时按三个节点拆分报告。X2另做 `h2`、`[h2,q2]`、`[h2,c,r]`、`[h2,q2,c,r]` 四项递进对照；`h2`与`h2'`在测试折按 `r=0/1` 分层，防止把显式质量码或审计控制泄漏误归于财务表示本身。
- Ridge 对输入和输出使用 split 0 的逐列均值/标准差，`alpha∈{0.1,1,10,100}`，按 split 1 的逐字段宏平均 NRMSE 最小选择。
- MLP 为一层隐藏层的两层线性网络，隐藏宽度 `min(256,2×输入维数)`，ReLU，AdamW，学习率 `1e-3`、权重衰减 `1e-4`、批量 1024，最多 30 轮、耐心 4 轮；攻击随机种子固定为 20261020。按 split 1 宏平均 NRMSE保存最佳轮。MLP用于 `h1/h2/h2'/h3/部署全视图` 的seed42与六模型联合主端点；q/c递进和实现视图用Ridge完成归因。
- 主端点在 split 1 上从 Ridge 与 MLP 中选出一个主攻击器；测试折不能参与这一选择。Ridge另补六个单种子稳定性，MLP不做六次单种子复制。
- PCA 与高斯随机投影仅作单模型逐节点参照，使用 `min(对应h内容维数,目标维数)` 维，并在各节点原 `x` 的split 0拟合。它们在评价样本上需要先读取目标输入再编码，属于“等维通用压缩可恢复性参照”，不属于现实攻击器，也不用于泄漏判定。联合视图维数超过目标维数时，PCA会退化为无损上界，只在文字中说明，不重复计算。
- 连续重构主判据为主攻击器相对常数攻击器的宏平均 NRMSE下降量；95%区间使用500次企业聚类配对重抽样。年度内先按字段宏平均，三年再等权。测试企业另按是否曾在split 0出现分层报告。
- 属性攻击使用直接L2 Logistic而非仅复用连续重构值，`C∈{0.01,0.1,1,10}`只按split 1选择。X1登记全部 `missing::` 字段和市场类型；X2登记全部 `missing::` 字段；X3_base登记8个 `missing::` 字段及前5项高管事件是否发生。标准化二值字段用split 0的两个取值原型还原；事件状态使用冻结缩放参数逆变换后以原始计数大于0判定。缺失状态报节点宏AUC，高管事件报宏AUC，市场类型另报多类accuracy和macro-F1；不再保留未事先定义的“少量分箱属性”。属性宏平均AUC区间使用200次企业聚类重抽样。
- 统计泄漏判据保持为：NRMSE下降量95%区间下界高于0，或属性宏平均AUC的95%区间下界高于0.5。另加描述性实用分级：NRMSE相对常数下降 `<5% / 5%–20% / >20%` 为弱/中/强；属性AUC `0.50–0.60 / 0.60–0.80 / >0.80` 为弱/中/强。统计显著但未达实用门槛只称“微弱泄漏”。PCA/随机投影参照不参与判定。

## 10. 第一阶段主攻击的执行顺序（正式全样本评价前冻结）

正式审计先运行决定是否启动防护训练所需的十个主端点：单模型和六模型联合视图分别评价 `h1`、`h2`、`h2'`、`h3` 和部署全视图。连续反演仍使用500次企业聚类重抽样。为在全量X2缺失位上完成直接属性攻击，第一阶段使用一个多输出线性 Logistic 头，一次矩阵运算联合拟合全部预登记属性；优化器固定为AdamW（学习率0.01、权重衰减0.0001、正类权重上限20），最多20轮并仅按split 1损失早停，不看测试折调参。属性区间先用20次企业重抽样作筛查。第二阶段再补齐第9节登记的C网格、200次属性区间、q/c递进归因、实现视图和通用压缩参照。

第一阶段的“具有实际量级的经验泄漏”门槛固定为：NRMSE改善至少0.05且95%区间下界大于0，或直接属性攻击宏AUC至少0.60且筛查区间下界大于0.5。只满足统计方向的结果记为微弱可恢复性。六模型部署全视图达到任一门槛，即可进入防护设计；不会因为单模型结果较弱而停止联合攻击。

首版逐字段SGD实现虽已完成部分2020端点，但在六模型X2上需要串行拟合约120个分类器，计算不可接受，且没有生成完整manifest。该未完成目录保留为工程记录，不作结果；在查看六模型X2和部署全视图结果前改用上述数学目标相同的多输出实现，并从新目录 `primary-audit-v2-formal` 重新运行全部端点。
